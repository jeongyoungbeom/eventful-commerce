# 로그인 실패와 비밀번호 재설정의 저장 계약

USER·SELLER 로그인은 계정 행을 잠그고 인증한다. InvalidCredentialsException은 인증 거부 응답이지만 감사 로그·실패에 따른 DB 계정 잠금은 커밋한다. 다른 저장·처리 오류는 기존 롤백 규칙을 유지한다. IP/이메일 실패 횟수는 각각 Redis 단일 키 Lua로 증가와 만료를 함께 처리한다. 요청 제한은 같은 스크립트 안에서 판정·증가·TTL을 처리하는 고정 창이며 차단된 요청이 만료를 연장하지 않는다. 과거 만료 없는 키도 만료를 복구한다.

현재 비밀번호 재설정은 USER API에 적용된다. 같은 계정의 로그인과 재설정이 행 잠금을 공유하며 잠금을 얻은 뒤 재설정 토큰을 다시 검증한다. 기존 USER refresh token의 Redis 폐기를 완료한 다음 비밀번호를 저장한다. Redis 폐기가 실패하면 DB 변경과 재설정 토큰을 보존한다. 이후 DB 저장·커밋이 실패하면 비밀번호는 롤백하지만 이미 폐기한 refresh token은 복구하지 않는다. 재설정 토큰이 소비된 뒤 실패했다면 새 재설정 링크를 요청해야 한다. PostgreSQL과 Redis 사이의 분산 트랜잭션은 추가하지 않는다.

새 refresh token에는 임의 jti를 넣어 같은 초의 재로그인도 다른 값을 발급한다. 새 로그인 뒤에도 이전 refresh token은 거부된다. 이미 발급된 access token은 현재 정책대로 서명된 만료 시각까지 유효하다. 기본 유효기간은 1시간이며 비밀번호 재설정에 따른 즉시 access 폐기는 구현하지 않는다.
